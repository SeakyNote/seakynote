## vba设置表格列宽

```Visual
Sub 彻底修复并统一表格列宽()
    Dim tbl As Table
    Dim rw As Row
    Dim W1 As Single, W2 As Single, W3 As Single, W4 As Single
    Dim W_merged As Single
    
    ' ================= 自定义宽度设置（单位：厘米） =================
    W1 = 3.0 * 28.35   ' 第1列宽（测试过程名称、测试步骤等标签列）
    W2 = 4.5 * 28.35   ' 第2列宽（新建场景等内容列）
    W3 = 3.0 * 28.35   ' 第3列宽（测试过程标识）
    W4 = 4.5 * 28.35   ' 第4列宽（CSU01等编号列）
    ' ==============================================================
    
    ' 计算合并行（2格行）右侧大格子的总宽度 = 第2列 + 第3列 + 第4列
    W_merged = W2 + W3 + W4
    
    Application.ScreenUpdating = False
    On Error Resume Next
    
    For Each tbl In ActiveDocument.Tables
        ' 1. 禁止 Word 根据文字/图片自动撑大表格
        tbl.AllowAutoFit = False
        
        ' 2. 遍历表格的每一行，分别处理 4 格行 和 2 格行
        For Each rw In tbl.Rows
            If rw.Cells.Count = 4 Then
                ' 针对标准 4 格行（第1行）
                rw.Cells(1).Width = W1
                rw.Cells(2).Width = W2
                rw.Cells(3).Width = W3
                rw.Cells(4).Width = W4
            ElseIf rw.Cells.Count = 2 Then
                ' 针对合并后的 2 格行（操作步骤、测试结果说明等）
                rw.Cells(1).Width = W1          ' 确保左侧列宽与第1列绝对对齐
                rw.Cells(2).Width = W_merged    ' 右侧大列宽度等于后三列之和
            End If
        Next rw
    Next tbl
    
    Application.ScreenUpdating = True
    MsgBox "所有表格列宽已完美对齐！", vbInformation, "修复完成"
End Sub
```

## word文档禁止图片压缩

出现这种情况，是因为 **Word 默认开启了“保存时自动压缩图片”的功能**。

当你刚把图片放进 Word 时，Word 内存中调用的还是原始的高清图片；但是当你**保存并关闭**后，Word 会按照默认设置强制降低图片的分辨率（通常压缩到 150dpi 或 220dpi）以减小文件体积。当你重新打开时，加载的就是已经被压缩过的低清图片了。

你可以通过以下几种方法彻底解决这个问题：

---

### 核心解决方法：关闭 Word 的自动压缩功能（设置“高保真”）

#### 第一步：修改 Word 设置（防止再次压缩）

1. 打开 Word，点击左上角的 **「文件」** \rightarrow **「选项」**。
    
2. 在弹出的窗口中，选择 **「高级」**。
    
3. 向下滚动找到 **「图像大小和质量」** 区域：
    
    1. 在下拉菜单中选择 **「所有新文档」**（这样以后新建的所有文档都不会压缩图片）。
        
    2. **勾选「不压缩文件中的图像」**。
        
    3. 将 **「默认分辨率」** 设置为 **「高保真」**（如果没有“高保真”，请选择最高的 **330 ppi**）。
        
4. 点击 **「确定」** 保存设置。
    

---

### ⚠️ 重要提醒（非常关键）

- **已经变模糊的图片无法自动还原**： 因为原图的像素在上次保存关闭时已经被 Word 永久删除了。在完成上述设置后，你需要**把那张清晰的原图重新插入/复制进文档**，然后保存。这次再关闭重新打开，图片就不会再变模糊了。
    

---

### 提高清晰度的其他辅助技巧

1. **避免直接「复制/粘贴」，改用「插入图片」**
    
    1. 从网页、微信或截图软件直接 `Ctrl+C` 然后 `Ctrl+V` 到 Word 里，有时会被系统转换为低质量的位图（如临时 BMP/DIB）。
        
    2. **建议**：先将图片保存为本地文件（`.png` 格式最佳），然后在 Word 中点击 **「插入」\rightarrow「图片」\rightarrow「此设备」**。
        
2. **文档格式必须是** **`.docx`**
    
    1. 如果你的文档是老版本的 `.doc` 格式，图片的压缩会非常严重。请务必另存为 **`.docx`** 格式。
        
3. **如果是图表、图标或流程图，优先使用矢量图（SVG / EMF）**
    
    1. 如果你的图片是矢量图（例如从 Visio、Illustrator、PPT 导出的），可以保存为 **`.svg`** 格式再插入 Word。矢量图在 Word 里无论放大多少倍、无论怎么保存关闭，永远都是绝对清晰的。
        

## 内外部工时预估

**企业必须进行内部的项目工时预估，并持续迭代。仅仅给外部（客户）提供工时预估是远远不够的，甚至是极其危险的。**

外部预估和内部预估在商业逻辑中扮演着完全不同的角色：**外部预估解决的是“商务与定价”问题，而内部预估解决的是“成本、交付与组织能力进化”问题。**

以下从四个维度深度解析，为什么企业必须做好内部工时预估并不断迭代：

---

### 一、 外部预估 vs 内部预估：本质目标的差异

|   |   |   |
|---|---|---|
|维度|外部预估（面向客户/销售）|内部预估（面向团队/交付）|
|核心目的|商务报价、合同承诺、范围基准、管理客户预期|资源排期、成本控制、风险预警、效能度量|
|颗粒度|通常较粗（按模块、按阶段、按人月/人天）|较细（按任务、按功能点、按具体角色）|
|容错率|包含商务谈判空间、利润率和风险缓冲（Buffer）|力求“真实”，剔除虚报，反映实际研发能力|
|动态性|签订合同后相对静态（除非触发变更流程）|必须高度动态，随着项目推进不断修正|

如果只做外部预估，企业就相当于**“用一个商务承诺来指导具体的生产制造”**，必然会导致交付失控。

---

### 二、 为什么必须做内部工时预估并“不断迭代”？

#### 1. 应对“不确定性锥形”（Cone of Uncertainty）

在项目初期，由于需求模糊、技术方案未定，预估的误差可能高达 ±200% 到 ±400%。

- **不断迭代的意义：** 随着项目的推进（需求明确、架构确立、核心技术打通），团队掌握的信息越来越多。**持续迭代内部工时，就是逐步收窄误差范围的过程**。只有动态调整工时，项目经理才能准确预判：**项目到底会不会延期？最终成本会不会超支？**
    

#### 2. 真实的成本控制与利润核算

- 外部预估决定了你的**收入上限**（比如合同金额 100 万，按 50 人天报价）。
    
- 内部预估和实际消耗决定了你的**实际成本**。
    
- 如果不进行内部细化迭代，项目往往会陷入**“以为赚钱，结项发现亏损”**的窘境。通过内部工时迭代，管理层可以在项目进行到 30% 时，就能发现“实际工时可能会超标 50%”，从而提前采取应对措施（如缩减非核心范围、优化方案）。
    

#### 3. 产能管理与多项目资源调度

企业通常同时运转多个项目。

- 内部工时的动态迭代，能清晰展示**团队成员未来的真实负荷（Capacity）**。
    
- 如果不迭代内部工时，资源经理就无法知道下个月张三到底是有空支援新项目，还是已经严重超载。这会导致要么人员闲置（资源浪费），要么团队严重过载引发离职潮。
    

#### 4. 建立企业的“度量资产”与组织能力进化

预估是一门“经验科学”。**不记录、不对比、不迭代，团队就永远无法提高预估准确度。**

- **内部迭代的闭环：** 初始预估 \rightarrow 过程修正 \rightarrow 实际消耗工时 \rightarrow 项目复盘。
    
- 通过复盘“为什么原本预估 3 天的任务实际做了 8 天”，企业可以沉淀出真实的技术基线（例如：开发一个标准支付接口需要 40 工时），从而让下一次给外部客户的报价**更有底气、更具竞争力**。
    

---

### 三、 仅给外部做预估的“致命陷阱”

如果企业放弃内部预估与迭代，通常会掉入以下陷阱：

1. **“学生综合征”与“帕金森定律”爆发：** 如果只告诉团队“这个项目客户买了 3 个月”，团队很可能会在前 2 个月松懈，最后一个月疯狂加班，产出大量低质量代码（帕金森定律：工作会自动膨胀，占满所有可用时间）。
    
2. **风险后置（交付暴雷）：** 直到交付前一周，项目经理才发现进度只完成了 50%，此时除了“无限期延期”或“通宵加班上线一堆 Bug”之外，毫无挽回空间。
    
3. **甩锅文化与内耗：** 销售抱怨交付团队效率低（“明明给你们留了足够时间”），研发抱怨销售胡乱承诺（“这个需求根本不可能在这个时间内做完”）。缺乏内部细化预估作为客观依据，责任永远界定不清。
    

---

### 四、 企业落地内部工时预估的 3 个实用建议

为了避免内部工时预估演变成“官僚主义”或“形式主义”，企业应遵循以下原则：

1. **不要将工时预估作为“绩效考核的惩罚工具”：** 如果员工因为“实际用时超过了预估”而受罚，他们就会在下一次预估时疯狂注水（Padding）。内部预估应该被视为**“对未来的科学预测”**，鼓励真实反馈。
    
2. **敏捷迭代，采用滚动式规划（Rolling Wave Planning）：** 没必要在一开始就把半年后的任务精确到小时。遵循“远粗近细”——对未来 1-2 周的迭代做精细工时预估，对后续阶段做粗颗粒度（故事点/人天）预估，每周/每两周滚动刷新一次。
    
3. **重视“方差分析”而非绝对精准：** 重点关注**“预估 vs 实际”偏差最大的那 20% 任务**。是遇到了技术卡点？需求变更？还是初级员工能力不足？分析这些偏差，正是组织能力提升的契机。
    

---

### 总结

- **外部工时预估**是给客户看的商业契约，决定了你能**收多少钱**；
    
- **内部工时预估与迭代**是内部运营的仪表盘，决定了你**能赚多少钱、交付质量如何、以及团队能否走得长远**。
    

成熟的企业，一定是**“外松内紧、外稳内敏”**：对外给出审慎、有保护垫的承诺，对内进行高频、敏捷的工时拆解与动态迭代。
